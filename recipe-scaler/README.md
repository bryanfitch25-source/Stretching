# Yield — Recipe Scaler (Android)

A local-only recipe app: add recipes, then scale every ingredient live by
servings or by pan size, in imperial or metric, with sensible rounding. No
backend, no account — everything lives on the device via the Capacitor
Preferences plugin (a thin native wrapper around Android's SharedPreferences).

This folder is a self-contained Capacitor project living inside the
`Stretching` repo (see the repo root for the unrelated StretchLine PWA).

## Why Capacitor Preferences instead of SQLite

The dataset is a personal recipe box (dozens to a few hundred recipes),
read/written as a whole, with no querying needs beyond an in-memory search
filter. A single JSON blob under one Preferences key gives full persistence
with zero native SQL dependency, no migrations, and trivial backup (the
blob *is* the backup). If you outgrow this — thousands of recipes, or a
need for real queries — swap `www/js/storage.js` for `@capacitor-community/sqlite`;
nothing else in the app depends on the storage format.

## Design identity

- **Palette**: warm cream paper background, deep coffee-ground ink text,
  terracotta for primary actions, sage green for "done", mustard for
  step numbers/highlights — the colors of a well-loved kitchen notebook,
  not a SaaS dashboard.
- **Type**: a serif system font (Georgia) for titles and step numbers —
  handwritten-recipe-card feel — paired with the system sans-serif for
  body text and all numbers, which must stay unambiguous at a glance.
  Both are system fonts: zero network dependency, since the app is fully
  offline.
- **Layout**: phone-first, single pane at a time, with big (48px+) tap
  targets throughout for use with wet or floury hands. On tablets/wide
  screens (≥760px) the layout switches to a persistent master-detail
  split view (recipe list always visible on the left).
- Full light/dark mode via `prefers-color-scheme`, visible focus rings,
  and safe-area padding (`env(safe-area-inset-*)`) for notches/gesture bars.

## Running locally (browser, for quick iteration)

No build step — plain HTML/CSS/JS. Data persists to `localStorage` when
there's no native Capacitor runtime (i.e. in a plain browser), and to
native Preferences once running inside the Android app.

```bash
cd recipe-scaler
npm install
npm start          # serves www/ at http://localhost:8100
```

## Turning this into an Android app

You'll need [Android Studio](https://developer.android.com/studio) (which
bundles the Android SDK) installed locally — this can't be done inside a
sandboxed CLI session.

```bash
cd recipe-scaler
npm install
npx cap add android      # generates the android/ native project
npx cap sync android      # copies www/ + plugins into it
npx cap open android      # opens the project in Android Studio
```

### Setting the minimum SDK to API 36

Play Store requires new/updated apps to target API 36 (Android 16) by
August 31, 2026. `npx cap add android` scaffolds a project pinned to API 34
on an older Android Gradle Plugin, which doesn't support compileSdk 36 —
you need to bump three things together. **This exact combination has been
build-verified in CI-less sandbox testing** (`./gradlew assembleDebug` and
`./gradlew bundleRelease` both succeeded against SDK Platform 36):

1. `android/variables.gradle`:
   ```gradle
   minSdkVersion = 24          // or higher, your call on device support floor
   compileSdkVersion = 36
   targetSdkVersion = 36
   ```
2. `android/build.gradle` — bump the Android Gradle Plugin (the scaffolded
   8.2.x doesn't understand compileSdk 36):
   ```gradle
   classpath 'com.android.tools.build:gradle:8.10.0'
   ```
3. `android/gradle/wrapper/gradle-wrapper.properties` — AGP 8.10.0 requires
   Gradle ≥ 8.11.1:
   ```
   distributionUrl=https\://services.gradle.org/distributions/gradle-8.11.1-all.zip
   ```

Then, in Android Studio's SDK Manager, install **SDK Platform 36** and
**Build-Tools 36.0.0** if prompted (Studio will prompt automatically on
first sync if they're missing). JDK 17+ is required by AGP 8.10 — recent
Android Studio versions bundle a compatible JDK automatically.

### Renaming the app / bundle ID before publishing

Both are placeholders — change them **before** your first release build,
since the Android `applicationId` is very painful to change after
publishing:

1. In `capacitor.config.json`, set `appId` (reverse-DNS, e.g.
   `com.yourname.yield`) and `appName`.
2. Re-run `npx cap sync android` (or, if you already ran `cap add
   android` once with the placeholder, easiest is to delete the
   generated `android/` folder and re-run `npx cap add android` fresh
   with the new config).

### Icons

`www/icons/icon.svg` is a simple placeholder mark (a mixing bowl + scale
arrows on a terracotta field). Use Android Studio's **Image Asset
Studio** (right-click `android/app/src/main/res` → New → Image Asset) to
generate the full adaptive-icon PNG set from it, or design your own
launcher icon — Play Store also requires a separate 512×512 hi-res icon
and a 1024×500 feature graphic for the store listing, which this repo
does not include.

### Building a signed .aab for the Play Store

1. In Android Studio: **Build → Generate Signed Bundle / APK…**
2. Choose **Android App Bundle**.
3. If you don't have a signing key yet, click **Create new…** and generate
   a keystore. **Back this file up somewhere safe outside this repo** — if
   you lose it, you can never update this app listing again under the same
   identity.
4. Fill in the keystore path/passwords, choose the `release` build variant.
5. Android Studio outputs the signed `.aab` (typically under
   `android/app/release/`).

Equivalent CLI path once you have a keystore and have configured signing
in `android/app/build.gradle` (`signingConfigs`):

```bash
npx cap sync android
cd android
./gradlew bundleRelease
# output: android/app/build/outputs/bundle/release/app-release.aab
```

## Build verification

The full pipeline above (`cap add android` → the three version bumps →
`./gradlew assembleDebug` / `./gradlew bundleRelease`) has been run
end-to-end and both succeed: a working `app-debug.apk` and an
`app-release.aab` were produced. The release bundle from that run is
**unsigned** (no `signingConfig` is wired up in `app/build.gradle` — that's
deliberate, since a real signing key has to be yours, not baked into this
repo). Follow "Building a signed .aab" below to produce an upload-ready one.

## What you still need to do in Play Console (can't be done for you)

- Create a Play Console developer account (one-time $25 fee) if you don't
  have one.
- Generate/manage your **app signing key** (Play Console now manages
  upload keys vs. app signing keys separately — follow its Play App
  Signing enrollment flow).
- Create the app listing and upload the signed `.aab`.
- **Store listing assets**: a 512×512 hi-res icon, a 1024×500 feature
  graphic, and at least 2 phone screenshots (take these from a running
  build/emulator) — none of these are generated here.
- Fill in the **Data safety** section — this app collects no data, so
  you'll declare "No data collected."
- Host `privacy-policy.html` somewhere public (GitHub Pages, your own
  site, etc.) and link that URL in the Play Console listing — Play
  requires a live URL, not an uploaded file. Fill in the `[DATE]` and
  `[YOUR CONTACT EMAIL]` placeholders in that file first.
- Complete Play Console's content rating questionnaire and target
  audience section.
- Submit for review.

## Testing checklist before you build a release

- Add a recipe, edit it, delete it — confirm the list updates.
- Force-close and reopen the app (or the browser tab) — confirm recipes
  persisted.
- On the recipe detail view: move the servings stepper up/down and watch
  quantities rescale; switch to pan-size mode and change pan dimensions;
  toggle imperial/metric and confirm units convert without producing
  awkward fractions.
- Select 2+ recipes from the list (shopping cart icon), build a shopping
  list, confirm a shared ingredient (e.g. "flour" in two recipes) is
  summed into one line.
- Tap "Share / export as text" and confirm the native share sheet (or
  clipboard fallback) fires with a readable plain-text list.
- Toggle device dark mode and confirm contrast/legibility hold up.
- Resize to a tablet width (or run on a tablet emulator) and confirm the
  master-detail split layout appears.
